Ecom Microservice GraphQL

An event-driven e-commerce backend split across Node.js microservices behind a unified GraphQL gateway.

This is a documentation/showcase page for the project — it does not run the full microservices stack live (the app depends on MongoDB, Kafka, and three Dockerized services running together). For the full source and setup instructions, see the GitHub repository.

Overview

Ecom Microservice GraphQL is a scalable e-commerce platform built around three independent services — user, product, and order — each with its own MongoDB store. A GraphQL API gateway sits in front of them, giving clients a single unified schema instead of three separate REST APIs. Kafka decouples the services from each other so a change in one (e.g. an order being placed) can be published as an event and consumed asynchronously by the others, without direct service-to-service calls.

Key Features

  • Three independent Node.js/Express microservices (user, product, order), each with its own MongoDB store
  • Unified GraphQL API gateway (Apollo Server) fronting all three services
  • Kafka event bus for asynchronous, decoupled communication between services
  • Per-service Dockerfiles plus a root docker-compose.yml to run the whole stack together
  • Integration tests per service (Jest)

Tech Stack

Node.js Express MongoDB / Mongoose Apache Kafka GraphQL (Apollo Server) Docker & Docker Compose

Architecture

ecom-microservice-graphql/
├── user-service/         # User registration, auth — own MongoDB store
├── product-service/      # Product catalog CRUD — own MongoDB store
├── order-service/        # Order management — own MongoDB store
├── graphql-gateway/      # Apollo Server — unified schema over all 3 services
├── kafka/                # Topic config + consumers for cross-service events
├── docker-compose.yml    # Runs Mongo, Kafka, and all 4 services together
